# FPGA ↔ PC 联调步骤

> 给负责 PC 端的同学。按顺序做，每一步都能独立验证，出问题好定位。

---

## 一、接线与网络

```
PC1（出题人）──HDMI──► 板子 ──HDMI──► 显示器
                        │
                        └──网线──► PC2（你，收图 + 跑模型）
```

| 步骤 | 做什么 | 怎么确认对了 |
|---|---|---|
| 1 | 网线从 PC1 拔下，插到 PC2 | PC2 的网口灯亮 |
| 2 | PC2 网卡设 `192.168.1.105 / 255.255.255.0` | `ipconfig` 能看到这个地址 |
| 3 | 等 5 秒 | 网卡状态显示 **1 Gbps** |

> **1 Gbps 是硬要求。** 显示 100 Mbps 说明网线只有 4 芯，收不到视频。

## 二、分三个阶段验证

### 阶段 1：只用演示模式，不接模型

```bash
python pc_receiver.py
```

**预期：**

```
本机地址: ['192.168.1.105', ...]
监听 UDP :5000，等待帧 ...
  帧 123  460800 字节  完整 21 残缺 0  20.1 fps  → 回传 1 个框
  帧 144  460800 字节  完整 42 残缺 0  20.1 fps  → 回传 1 个框
```

同时**板子那台显示器上应该有一个红框在左右移动**。

这一步验证的是：收包、拼帧、解码、回传，**和模型完全无关**。
如果这步不通，不要往下走。

### 阶段 2：接模型，但先不回传

```bash
python pc_receiver.py --no-send
```

把 `demo_model()` 换成你的模型，先确认：

- 能稳定收到帧（`残缺 0`）
- 模型能跑起来不掉帧（20 fps 输入，推理要快于 50 ms）
- 存一帧看看：`python pc_receiver.py --save f.png`

### 阶段 3：打开回传

去掉 `--no-send`，让模型结果回到 FPGA，看显示器上的框对不对。

**重点检查：坐标必须是 1280×720 原始帧坐标系**，不是 640×360。
如果你在 640×360 上算的框，要乘 2。

## 三、出问题怎么定位

按现象查，从下往上：

| 现象 | 原因 | 检查 |
|---|---|---|
| 一包都收不到 | 网卡地址不对 | 是不是 `192.168.1.105` |
| 一包都收不到 | 链路不是千兆 | 网卡状态是不是 1 Gbps（换 8 芯网线） |
| 收得到但 `残缺` 很多 | 收包循环里做了耗时操作 | 收到帧立刻返回，推理放外面 |
| 画面斜切/错位 | 把 32 字节应用头当成图像了 | 图像数据从包的第 32 字节开始 |
| 画面颜色不对 | RGB565 高低字节反了 | `byte0=RRRRRGGG`，`byte1=GGGBBBBB` |
| 画面上有横条错乱 | 没按 `packet_id` 重排 | 必须按序号拼接 |
| 有画面但没框 | 回传没发出去 | 用 `--no-send` 对比；检查目的地址 `192.168.1.255:5002` |
| 有框但位置不对 | 坐标系用错 | 框必须用 1280×720 坐标 |

## 四、协作上的注意

1. **只有一根网线、一块板子**：你连着的时候 PC1 收不到数据，反之亦然。
   需要来回验证时提前说一声。

2. **改 FPGA 要重新烧录**（约 2 分钟），烧录期间链路会断几秒。

3. **板子的 HDMI 输入不能断**：显示器必须接着，否则 PC 拿不到 EDID、
   HDMI 输出会停，FPGA 收不到画面，整条链路就静默了。

4. **录一份基准**：先跑通演示模式时，存一张 `f.png` 当作"链路正常"的参照，
   以后出问题先比对这张图。

## 五、接入 YOLOP 模型（2026-11-02 已跑通）

环境：`E:\anaconda3\envs\my_pytorch\python.exe`（torch 1.8.1+cu111，RTX 3050 Ti）

```bash
python pc_receiver.py ^
  --model "C:\Users\Lenovo\Desktop\YOLOP_v3_全功能使用包_20261102" ^
  --device cuda:0 --show --record out.mp4
```

实测：推理 **38.9 ms/帧**，端到端 **19.4 fps**，每帧 8~13 个框，
**FPGA 那块显示器上绿框正常框住车辆并跟随运动**。

`yolop_adapter.py` 做了三件事：

| 做什么 | 说明 |
|---|---|
| torch 兼容补丁 | 本机是 torch 1.8.1，缺 `inference_mode` 和 `weights_only`，只在本进程内打补丁，不改队友的包 |
| 类别映射 | vehicle=0 person=1 traffic_light=2 rider=3 |
| 坐标换算 | 模型输出按 640×360 算，乘 2 换回 1280×720 |

> 注意：模型看到的画面里**带有已画好的框**（2 像素细线）。这是刻意保留的
> ——上传必须取自输出寄存级，否则 FPGA 屏幕上就不画框了。实测不影响检测。

## 六、当前已知限制

| 项 | 现状 |
|---|---|
| 帧率 | **20 fps**（不是 30），采集和发送目前串行 |
| 分辨率 | 640×360 RGB565，固定 |
| 框数量 | 最多 32 个 |
| 帧号 | 单调递增，可用于判断有没有丢帧 |
