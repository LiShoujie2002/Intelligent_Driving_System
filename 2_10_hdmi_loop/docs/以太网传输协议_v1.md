# FPGA ↔ PC 以太网传输协议 v1.4

> 适用范围：紫光同创 PG2L200H（盘古 200Pro）+ RTL8211F 千兆 PHY
> 物理链路：板载 RJ45 网口，直连 PC
> 本文描述**系统架构**和**线上字节**，不涉及 FPGA 内部实现细节。

---

## 0. 一页速览

```
HDMI 输入 ──► FPGA 采集 + ÷2 降采样 ──UDP──► PC 推理 ──UDP──► FPGA 叠框 ──► HDMI 显示
             640×360 RGB565          118 Mbit/s      32 个框
```

| 项目 | 决定 |
|---|---|
| 传输层 | **UDP over IPv4**（不用 TCP） |
| 链路层 | Ethernet II |
| 字节序 | 全部**大端（网络序）** |
| FPGA 上传尺寸 | **640×360 RGB565，30 fps**（1280×720 ÷2 精确抽取） |
| 带宽 | **≈ 118 Mbit/s（14.8 MB/s）**，千兆占用 12% |
| MTU | IP 总长 ≤ 1500，每包图像数据 ≤ **1440** 字节 |
| 应用头 | **固定 32 字节** |
| UDP 校验和 | **填 0（不启用）** |
| IPv4 头校验 | FPGA 计算 |
| 以太网 FCS | FPGA 的 MAC 计算 |
| ARP | **不实现**，两端都用广播（见 7.4） |
| FPGA 侧存储器 | **只用片上 BRAM，不用 DDR** |

> **模型输入尺寸目前未知**（队友换了新模型，在 PC 上跑）。
> 协议不依赖它：`dst_width/dst_height` 在包头里，PC 想缩到多少自己缩。

### 实测状态（2026-11-01，板上验证）

| 项 | 状态 |
|---|---|
| 视频上传 | ✅ **640×360 RGB565 @ 20 fps，零丢包** |
| 检测结果回传 | ✅ PC 发框 → FPGA 解析 → HDMI 上画框，**位置逐像素核对无误** |
| 帧率 | ⚠️ **20 fps**（不是 30）：采集和发送目前是串行的，还没优化 |
| PC 端要求 | 网卡 **192.168.1.105/24**，普通 UDP socket，不需要管理员权限 |

### 1.3 PC 侧职责

| 步骤 | 说明 |
|---|---|
| 收包重组 | 按 `frame_id`/`packet_id`/`packet_total` 拼一帧，缺包丢帧 |
| 格式转换 | RGB565 → RGB888 |
| 尺度变换 | 640×360 → **模型输入尺寸（未知，由模型决定）** |
| 归一化 | 按训练时的配置 |
| 推理 | PyTorch / ONNX Runtime |
| NMS | 标准后处理 |
| 坐标反算 | 模型输入 → 640×360 → 1280×720（×2） |
| 回传 | UDP 广播，每帧一个包 |

### 1.4 为什么这样分工

- **FPGA 只做确定性、流水线友好、不需要浮点的事**：抽取、滤波、搬运、打包、画矩形。
- **PC 做需要浮点、分支、大内存的事**：resize、推理、NMS、坐标反算。
- 这条分界线让 FPGA 侧**没有除法、没有浮点、没有查表**。

### 1.5 为什么是 ÷2 → 640×360

**两个轴都整除，零误差：**

```
1280 / 2 = 640
720  / 2 = 360
```

坐标反算就是 `x_src = x_dst × 2`，**精确整数**，框不会偏。

**2×2 均值滤波很便宜**（3 个加法器 + 1 次右移），但能消除最近邻抽取的混叠——这对小目标检测很重要。

对比其他档位：

| 方案 | 每帧字节 | 双缓冲 BRAM | 带宽 @30fps | 需要 DDR | 坐标映射 |
|---|---:|---:|---:|---|---|
| ÷4 → 320×180 | 115 KB | 230 KB | 30 Mbit/s | 否 | ×4（但太小） |
| **÷2 → 640×360** | **461 KB** | **922 KB（49%）** | **118 Mbit/s** | **否** | **×2** |
| 全图 1280×720 | 1,843 KB | 3,686 KB | 442 Mbit/s | **是**（1.87 MB 装不下） | ×1 |

**为什么不上 720p：** 输入 720p60 RGB888 有效像素率 1280×720×60×3 = **165.9 MB/s**，
输出全图 1280×720 RGB565 @30fps 只有 **55.3 MB/s**，差 3 倍，缓冲必须接近整帧（1.84 MB），
而片上 BRAM 总共 1.87 MB——双缓冲要 3.7 MB，**物理上装不下，必须上 DDR3**。

而 640×360 已经**比任何合理的小模型输入都大**，模型要的信息都在里面。

> 如果输入是 1080p，按同样规则 ÷2 得 960×540，协议不用改（只改头里的 `dst_width/height`）。

### 1.6 端到端时延估算

| 环节 | 估算 | 说明 |
|---|---|---|
| 采集一帧 | 33 ms | 30 fps |
| 降采样 + 帧缓存 | < 1 ms | 流水线 |
| 上传 | 37 ms @100M / 3.7 ms @1G | 缓冲后突发发送 |
| PC 推理 | 3 ~ 20 ms | 取决于模型和硬件 |
| 回传 | < 1 ms | 单包 |
| **合计** | **约 45 ~ 90 ms** | 约 2~3 帧延迟 |

对 ADAS 演示可以接受。要更低延迟就把发包与采集做成流水。

### 1.7 故障降级

| 故障 | FPGA 行为 |
|---|---|
| 网线断开 / PC 无回包 | 超过 500 ms 没收到检测结果 → 清空框表，只显示原图 |
| PC 推理报错 | PC 发 `count=0`，FPGA 清空框表 |
| 丢包导致整帧不完整 | PC 丢弃该帧，**不发**结果；FPGA 沿用上一帧的框，500 ms 后清除 |
| 以太网链路没起来 | 视频通路完全不受影响，仍能直通显示 |

> **降级原则：网口挂了，HDMI 直通必须还能用。** 这是基础任务1 的底线。

## 2. 设计约束（先看这段，避免按错假设实现）

1. **PC 收到的不是 720p 原图**，是 ÷2 降采样后的 640×360。
2. **包可以切在任意字节位置**，可能切在一行中间、甚至一个像素的两半之间。
   接收端必须按 `packet_id` 顺序拼成连续字节流，再当作图像解释。
3. **ARP 由协议栈自动处理**；若用自研 MAC，则硬编码目的 MAC（见 7.5 节）。
4. **UDP 校验和为 0**。IPv4 允许，Python/Windows 都能正常收。
5. **FPGA 侧不使用 DDR**。全部图像缓冲在片上 BRAM 里。

## 3. 线上分层

```
┌─────────────────────────────────────────────┐
│ Ethernet II  14 字节                        │
├─────────────────────────────────────────────┤
│ IPv4         20 字节（无选项）              │
├─────────────────────────────────────────────┤
│ UDP           8 字节                        │
├─────────────────────────────────────────────┤
│ 应用头       32 字节                        │
├─────────────────────────────────────────────┤
│ 数据        ≤1440 字节                      │
└─────────────────────────────────────────────┘
              + 4 字节 FCS（MAC 生成，应用看不到）
```

单包最大占用：14 + 20 + 8 + 32 + 1440 = 1514，加 FCS = 1518，符合标准 MTU。

---

## 4. 应用头（32 字节）

所有多字节字段为**大端**。

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | `magic` | 固定 `0x50 0x4E 0x47 0x31`（ASCII `"PNG1"`） |
| 4 | 1 | `version` | 固定 `0x01` |
| 5 | 1 | `msg_type` | `0x01`=视频帧 `0x02`=检测结果 `0x03`=心跳 |
| 6 | 2 | `flags` | bit0 = `LAST`（本帧最后一包）；其余保留填 0 |
| 8 | 4 | `frame_id` | 帧号，从 0 单调递增，回绕后继续 |
| 12 | 4 | `packet_id` | 本包在帧内的序号，**从 0 开始** |
| 16 | 2 | `packet_total` | 本帧总包数 |
| 18 | 2 | `src_width` | 原始画面宽（1280） |
| 20 | 2 | `src_height` | 原始画面高（720） |
| 22 | 2 | `dst_width` | **本包图像数据**的宽（640） |
| 24 | 2 | `dst_height` | 本包图像数据的高（360） |
| 26 | 1 | `pixel_format` | `0`=RGB888 `1`=RGB565 `2`=GRAY8 |
| 27 | 1 | `resize_mode` | `0`=整数抽取（v1 固定用这个） `1`=等比留黑边 |
| 28 | 2 | `payload_len` | **本包图像数据字节数**，0..1440 |
| 30 | 2 | `reserved` | 填 0，接收端忽略 |

## 5. 视频帧（`msg_type = 0x01`）

### 5.1 帧的组成

一帧图像被切成 N 个 UDP 包：

```
packet 0:     packet_id=0,                payload_len=1440
packet 1:     packet_id=1,                payload_len=1440
...
packet N-1:   packet_id=N-1, flags.LAST=1, payload_len = 剩余字节数
```

除最后一包外，`payload_len` 都是 1440。

### 5.2 像素格式与字节序

**RGB565**（默认）
```
每像素 2 字节，高字节在前：
  byte[0] = RRRRRGGG
  byte[1] = GGGBBBBB
```

**RGB888**
```
每像素 3 字节：R, G, B
```

**GRAY8**
```
每像素 1 字节
```

### 5.3 图像排布

- 行优先：从上到下，每行从左到右。
- **没有行对齐填充**，`stride = dst_width × bytes_per_pixel`。
- 一帧总字节数 `frame_bytes = dst_width × dst_height × bytes_per_pixel`。

### 5.4 坐标映射

`resize_mode = 0`（整数抽取，v1 默认）：

```
x_src = x_dst × (src_width  / dst_width)     = x_dst × 2
y_src = y_dst × (src_height / dst_height)    = y_dst × 2
```

`resize_mode = 1`（等比留黑边，备用）：

```
scale = min(dst_width / src_width, dst_height / src_height)
pad_x = (dst_width  - src_width  × scale) / 2
pad_y = (dst_height - src_height × scale) / 2
x_src = (x_dst - pad_x) / scale
y_src = (y_dst - pad_y) / scale
```

### 5.5 示例：640×360 RGB565 @30fps

```
frame_bytes  = 640 × 360 × 2 = 460,800
packet_total = 460800 / 1440 = 320（整除，最后一包也是 1440）
线上字节/帧  = 320 × 1538     ≈ 492,160
带宽         = 492160 × 30    ≈ 14.8 MB/s ≈ 118 Mbit/s
```

千兆占用约 **12%**，百兆会超（需要 118 Mbit/s > 100），所以**必须千兆**。

## 6. 检测结果（`msg_type = 0x02`，PC → FPGA）

一个 UDP 包即可，不分片。

### 6.1 头部

同第 4 节，区别：

| 字段 | 值 |
|---|---|
| `msg_type` | `0x02` |
| `flags` | bit0=`LAST` 置 1 |
| `frame_id` | **回显**对应视频帧的 `frame_id`，FPGA 用它对齐 |
| `packet_id` | 0 |
| `packet_total` | 1 |
| `dst_width` / `dst_height` | 填 0 |
| `payload_len` | `count × 16` |

### 6.2 载荷：框数组

每个框 **16 字节**：

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | `x1` | 左上 x，**原始帧像素坐标**（0..1279） |
| 2 | 2 | `y1` | 左上 y（0..719） |
| 4 | 2 | `x2` | 右下 x |
| 6 | 2 | `y2` | 右下 y |
| 8 | 1 | `class_id` | `class_names[class_id]` |
| 9 | 1 | `subclass` | 红绿灯颜色等子类：0=无 1=红 2=黄 3=绿 |
| 10 | 1 | `confidence` | 0..100（整数百分比） |
| 11 | 1 | `reserved` | 0 |
| 12 | 4 | `reserved` | 0 |

**坐标必须在原始帧坐标系**。FPGA 直接拿来做矩形叠加，**不做任何换算**。

### 6.3 容量

FPGA 侧缓存 **最多 32 个框**。超过的丢弃（保留置信度最高的 32 个）。

`count = 0` 表示"本帧无目标"，FPGA 清空上一帧的框。

## 7. 地址与寻址（与当前实现完全一致）

### 7.1 实际配置

| 角色 | MAC | IP | 端口 |
|---|---|---|---|
| FPGA | `A0:B1:C2:D3:E1:E1` | `192.168.1.11` | 发 5000 / 收 5002 |
| **PC（必须）** | 网卡真实 MAC | **`192.168.1.105`** | 收 5000 / 发 5002 |

> **PC 网卡必须是 `192.168.1.105/24`。** FPGA 里的目的 IP 是写死的，
> 地址不对就一包都收不到。

### 7.2 FPGA → PC（视频）

```
目的 MAC = FF:FF:FF:FF:FF:FF   （广播）
源   MAC = A0:B1:C2:D3:E1:E1
目的 IP  = 192.168.1.105        （写死）
源   IP  = 192.168.1.11
目的端口 = 5000
源  端口 = 5000
```

### 7.3 PC → FPGA（检测结果）

```
目的 MAC = FF:FF:FF:FF:FF:FF   （广播，Python 需开 SO_BROADCAST）
目的 IP  = 192.168.1.255       （子网广播，也可以填 192.168.1.11）
目的端口 = 5002
```

### 7.4 不实现 ARP

两端都不用 ARP：

- FPGA 发视频用**广播 MAC**，不需要知道 PC 的 MAC
- PC 发检测结果用**子网广播** `192.168.1.255`，不需要知道 FPGA 的 MAC
- FPGA 收包时**不校验目的 IP**（`CHECK_IP=0`），MAC 接受广播或自身地址

好处：PC 端不用原始套接字、不用管理员权限、不用配静态 ARP 表。

代价：同网段的其他机器也能看到视频流（教室里演示时注意）。

### 7.5 现场检查清单

| 现象 | 检查 |
|---|---|
| 一包都收不到 | PC 网卡是不是 `192.168.1.105`；网线是否直连；是否经过交换机（可以，但要同网段） |
| 收到包但组不成帧 | `packet_id` 是否都用上了；`flags` bit0（LAST）有没有处理 |
| 画面错位/斜切 | 是否把 32 字节应用头当成图像了；`stride` 是否按 `dst_width×2` 算 |
| 颜色不对 | RGB565 高字节在前：`byte0=RRRRRGGG`，`byte1=GGGBBBBB` |

## 8. 校验与错误处理

| 层 | 校验 | 谁做 |
|---|---|---|
| 以太网 FCS | CRC32（poly 0xEDB88320） | FPGA MAC 生成 |
| IPv4 头 | 16 位反码和 | FPGA 计算，PC 协议栈校验 |
| UDP | **填 0（不校验）** | 无 |
| 应用层 | 无 CRC | — |

**接收端错误处理：**

- 用 `frame_id` + `packet_id` + `packet_total` 组装一帧
- 收到 `flags.LAST` 后检查 0..N-1 是否齐全；**缺包就丢弃整帧**
- `payload_len` 不等于 1440 但又不是最后一包 → 视为异常，丢帧
- 超过 200 ms 没等到下一包 → 丢弃当前帧，重置状态
- 丢帧时**不发送**检测结果

> 接自己的模型只需要改一个函数（文件里有注释说明）。
> 下面这段是同样的逻辑，作为理解协议用的精简版。

```python
import socket, struct, numpy as np

MAGIC = b'PNG1'
# magic ver type flags | frame_id packet_id | total sw sh dw dh | fmt resize plen rsv
HDR = struct.Struct('>4sBBHIIHHHHHBBHH')    # 32 字节
BOX = struct.Struct('>HHHHBBBBI')           # 16 字节
PORT_VIDEO, PORT_DETECT = 5000, 5002

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)
sock.bind(('0.0.0.0', PORT_VIDEO))

def recv_frame(sock, timeout=200):
    """收一帧。返回 (frame_id, dw, dh, pfmt, sw, sh, img_bytes) 或 None"""
    buf, total, fid = {}, None, None
    sock.settimeout(timeout / 1000.0)
    while True:
        pkt, _ = sock.recvfrom(2048)
        body = pkt[42:]                       # 14 Eth + 20 IP + 8 UDP
        (magic, ver, mtype, flags, frame_id, pid, ptot,
         sw, sh, dw, dh, pfmt, rmode, plen, _rsv) = HDR.unpack(body[:32])
        if magic != MAGIC or mtype != 0x01:
            continue
        fid, total = frame_id, ptot
        buf[pid] = body[32:32 + plen]
        if flags & 1:                          # LAST
            break
    if total is None or len(buf) != total:
        return None                            # 缺包丢帧
    data = b''.join(buf[i] for i in range(total))
    return frame_id, dw, dh, pfmt, sw, sh, data

def send_detections(sock, frame_id, boxes):
    """boxes: [(x1,y1,x2,y2,class_id,subclass,conf), ...]，全部是原始帧坐标"""
    out = b''.join(BOX.pack(x1, y1, x2, y2, c, s, conf, 0, 0)
                   for (x1, y1, x2, y2, c, s, conf) in boxes)
    assert len(out) % 16 == 0
    hdr = HDR.pack(MAGIC, 1, 0x02, 0x03, frame_id, 0, 1,
                   0, 0, 0, 0, 0, 0, len(out), 0)
    sock.sendto(hdr + out, ('255.255.255.255', PORT_DETECT))
```

### 9.1 坐标反算示例

```python
def to_source(x1, y1, x2, y2,
              model_w, model_h,          # 模型输入尺寸（未知，由模型决定）
              dst_w=640, dst_h=360):
    # ① 模型输入 -> 640×360
    sx, sy = dst_w / model_w, dst_h / model_h
    x1, x2 = x1 * sx, x2 * sx
    y1, y2 = y1 * sy, y2 * sy
    # ② 640×360 -> 1280×720（÷2 抽取，× 2）
    return int(x1)*2, int(y1)*2, int(x2)*2, int(y2)*2
```

> 实际实现时，**预处理和后处理必须严格互逆**。建议把预处理写成一个函数，
> 后处理直接用它记录的参数反算，而不是各写一遍。
